# 智能 PDF 自动填充引擎设计

## 1. 目标

将原有以“空白模板输出 / 脚本级表单填写”为主的能力，升级为可被 AI Agent 稳定调用的智能 PDF 自动填充链路：

- 自动识别 PDF 表单字段结构
- 识别字段的业务语义
- 从数据库、JSON、Excel、CSV 等多数据源自动取值
- 允许用户通过映射规则微调结果
- 输出已填充 PDF 和校验报告

## 2. 核心模块

### 2.1 字段语义分析模块

位置：

- `backend/pdf_autofill_engine.py`

能力：

- 基于 `pypdf` 读取可填写字段
- 识别 `text / checkbox / radio_group / choice`
- 使用 `pdfplumber` 提取邻近文本，推断字段标签
- 根据字段名、标签和规则推断业务语义，如：
  - `company_name`
  - `applicant_name`
  - `date`
  - `amount`
  - `phone`
  - `email`

### 2.2 知识库与推理引擎

能力：

- 内置常见业务字段语义规则
- 支持中文字段别名归一化，如：
  - `公司名 -> company_name`
  - `申请人 -> applicant_name`
  - `金额 -> amount`
- 根据字段类型自动转换值：
  - 复选框布尔值
  - 下拉选项值
  - 金额数值格式

### 2.3 多数据源接入

当前支持：

- DuckDB 数据库
- 用户上传 JSON
- 用户上传 CSV / Excel
- 提示词内联键值对

系统会将多种来源合并成统一上下文，再执行字段匹配与值推断。

### 2.4 映射规则

支持用户通过 JSON 规则文件覆盖默认推理结果：

- 按 `field_id`
- 按 `semantic_key`

用于解决：

- 模板字段命名不规范
- 企业内部字段与模板字段不一致
- 某些字段需要手工指定

### 2.5 结果验证机制

生成校验报告，检查：

- 必填项是否缺失
- 日期格式是否合理
- 邮箱格式是否正确
- 电话长度是否异常
- 金额是否为合法数值

校验结果输出为 JSON 文件，并作为下载产物提供给前端。

## 3. Agent 接入方式

当用户提出以下类型需求时：

- “根据 PDF 模板自动填充”
- “填写合同 PDF”
- “填写申请表 PDF”
- “根据模板生成已完成的 PDF 文件”

`supervisor_agent` 会直接路由到 `reporter_agent`，再由 `reporter_agent` 调用固定的 PDF 自动填充模板代码。

## 4. 执行策略

该链路采用本地子进程执行：

- 原因：需要导入项目内的 `backend.pdf_autofill_engine`
- 因此生成代码会带 `LOCAL_ONLY` 标记
- 执行器检测到该标记后，跳过 E2B，改走本地安全子进程

## 5. 产物

当前链路会输出：

- 已填充 PDF
- 校验报告 JSON

前端下载区会展示：

- `report_pdf`
- `validation_report`
